| # | 正面(问题) | 背面(答案) | 掌握 |

| 1 | 双指针三种形态?各适合什么题? | ① 对撞(相向,有序数组找两数/三数之和)② 快慢(同向,移除元素/移动零)③ 滑动窗口(同向夹区间,无重复子串/最小覆盖) | ⬜ |
| 2 | 双指针为什么能省时间? | 朴素枚举 (i,j) 对是 O(n²);双指针每次只动一个、每个元素至多被两端各访问一次 → 均摊 O(n)。精髓是「不回头」 | ⬜ |
| 3 | 对撞双指针原型 two_sum_sorted 怎么做?前提? | lo=0,hi=n-1;和太小 lo++、太大 hi--、等了返回。前提是【数组有序】(无序要先 sort 或用 HashMap) | ⬜ |
| 4 | LC11 盛水容器为什么移动【短】边? | 面积=宽×min(高)。宽在缩小,只有 min(高) 变大才能扳回。移动长边:宽变小、min 被短边卡死不变→只会更小;移动短边:min 可能变大→有希望。故贪心移动短边 | ⬜ |
| 5 | LC3 滑动窗口怎么维护? | 窗口 set 存已出现字符;右扩 for right;若 s[right] 在 set 里 → while 左缩(remove s[left],left++);add(ch);best=max(best, 宽) | ⬜ |
| 6 | LC3 嵌套了 while 为什么还是 O(n)? | right 只前进 n 次;left 总共也只前进 ≤n 次(每个字符至多 add/remove 各一次)。总操作 ≤2n → 均摊 O(n)。看「元素总访问次数」别看嵌套 | ⬜ |
| 7 | LC3 用 if 还是 while 收缩?用 list 还是 set? | 必须 while(缩到无重复);用 set(in/remove 是 O(1))。用 list 查找 O(n) 整体退化 O(n²) | ⬜ |
| 8 | LC15 三数之和整体思路?复杂度? | sort → 固定 i → 对撞 lo/hi 找 -nums[i]。O(n²)(外层 n × 内层对撞 n;排序 O(nlogn) 被吸收) | ⬜ |
| 9 | LC15 有几处去重?各干嘛? | 两处。① 固定 i 的去重:`nums[i]==nums[i-1]` 跳过(同首数上一轮已找全)。② 命中后 lo/hi 越过相邻重复值(否则塞重复三元组)。漏一处就有重复 | ⬜ |
| 10 | LC15 去重 i 为什么和 i-1 比不和 i+1 比? | 和 i-1 比 = 跳过【本轮重复】(上一轮已找全同首数);和 i+1 比 = 预判下轮,会漏解(如 [-2,0,0,2,2] 会在 i=0 误跳) | ⬜ |
| 11 | LC76 need[c] 的三种语义? | >0:t 还缺 c 这么多个(缺口);==0:刚好;<0:窗口里 c 超了(冗余,左缩时可丢) | ⬜ |
| 12 | LC76 为什么用 missing 整数不用 sum(need)? | 每次 while 都 sum(need.values()) 太慢。用 missing 增量维护:右扩时 need[ch]>0 才 missing-=1(只算真正补缺);左缩时出窗口后 need>0 才 missing+=1 | ⬜ |
| 13 | LC76 为什么用 Counter 不用 dict? | Counter 访问不存在 key 返回 0(安全);dict 会 KeyError。代码里 need[ch] 读 s 任意字符都安全。Java 要用 getOrDefault(c,0) | ⬜ |
| 14 | LC76 length 初值设什么?为什么? | length=len(s)+1(哨兵)。找不到时 length 仍 >len(s),最后 `if length<=len(s)` 区分返回 ""。设成 len(s) 会误判返回整个 s | ⬜ |
| 15 | 滑动窗口通用模板三步? | ① 右扩(把 s[right] 纳入窗口)② 不合法就 while 左缩到合法 ③ 更新答案。LC3 合法=无重复,LC76 合法=涵盖 t | ⬜ |
| 16 | 什么问题该用滑动窗口?(口诀) | 「求连续子数组/子串的极值,且窗口有单调性(右扩使条件变差、左缩使条件变好)」→ 用滑动窗口 | ⬜ |

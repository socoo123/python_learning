## §39.1 DP 是什么 + 什么时候用 🟡

**动态规划**的本质一句话:**把大问题拆成子问题,记住每个子问题的答案,避免重复计算**。

它和分治(如归并排序)的区别:分治的子问题**互不重叠**,DP 的子问题**大量重叠**。斐波那契 `f(5)` 会反复算 `f(3)`、`f(2)`——重叠子问题正是 DP 的舞台。

### 识别一道题是不是 DP(三个信号)

| 信号 | 说明 | 本章对应 |
|------|------|----------|
| **求最值**(最大/最小/最长/最短/最少) | "最少硬币""最长子序列""最少操作数" | §39.3/§39.4/§39.6 |
| **求方案数**(有多少种走法/组合) | "爬楼梯有几种走法" | §39.2 |
| **求可行性**(能不能凑出/到达) | "能不能凑成 target" | (变体) |

外加两个理论前提:**最优子结构**(大问题的最优解由子问题最优解拼成)+ **无后效性**(未来的决策只看当前状态,不关心怎么走到这的)。满足这两条,DP 基本跑不掉。

### 两把写法(背下来)

| 写法 | 思路 | Python 利器 | Java 怎么写 |
|------|------|------------|-------------|
| **自顶向下(记忆化搜索)** | 从大问题出发递归,顺手把算过的子问题缓存 | `@lru_cache(None)` 一行搞定 | 手写 `int[] memo = new int[n]; Arrays.fill(memo, -1);` |
| **自底向上(迭代填表)** | 从最小子问题开始,一格一格填 DP 表 | `dp = [0]*(n+1)` | 同样 `int[] dp = new int[n+1];` |

**选择原则**:能写出递推关系的优先自底向上(常数小、无栈溢出);递归关系天然直观的(爬楼梯、树形 DP)用 `@lru_cache` 爽一把。

> 🟡 **Java 对比**:Java 也有记忆化,但要你**自己维护 memo 数组**、判"是否算过"、传下标。Python 的 `@lru_cache` 是**装饰器**,自动用一个 dict 缓存"参数 → 返回值",你只管写干净的递归。这是 Python 刷 DP 题最大的爽点。

> ✅ **本章贯穿口诀**:**状态定义 + 转移方程 + 边界**。每道题先问三连:① `dp[i]`(或 `dp[i][j]`)代表什么?② 它从哪些状态转移来?③ 最小的、可以直接回答的边界值是几?

## §39.2 爬楼梯:climb_stairs(LC70)🟡

**题面**:你每次能爬 1 或 2 步,爬到第 `n` 阶共有多少种不同走法?

### 为什么这么做

关键洞察——**只看最后一步**:到达第 `n` 阶,你的最后一步要么从第 `n-1` 阶爬 1 步、要么从第 `n-2` 阶爬 2 步(没有别的可能)。所以:

```
f(n) = f(n-1) + f(n-2)
f(1) = 1   # 只能 1
f(2) = 2   # 1+1 或 2
```

这就是**斐波那契数列**!

为什么裸递归 `f(n)=f(n-1)+f(n-2)` 是 O(2ⁿ) 地狱?因为 `f(5)` 算 `f(4)+f(3)`,`f(4)` 又算 `f(3)+f(2)`——`f(3)` 被算了两次,越往下重复越多,呈指数爆炸。**子问题大量重叠** = DP 信号。

### 实现:@lru_cache 记忆化递归

```python
from functools import lru_cache

def climb_stairs(n: int) -> int:
    @lru_cache(None)
    def f(k: int) -> int:
        if k <= 2:        # 边界: f(1)=1, f(2)=2
            return k
        return f(k - 1) + f(k - 2)   # 转移方程
    return f(n)
```

**亮点**:递归函数 `f` 加 `@lru_cache(None)` 后,`f(3)` 第一次算完会被缓存,之后再调直接返回——把 O(2ⁿ) 砍成 O(n)。你写的代码和裸递归**长得一模一样**,只多一行装饰器。Java 想达到同样效果,得自己开 `int[] memo`、判 `-1`、填值,啰嗦得多。

> 为什么在函数内部再定义 `f` 而不是直接装饰 `climb_stairs`?——把缓存和公开 API 解耦,避免缓存被多次调用累积(可选习惯,把 `@lru_cache` 直接加到 `climb_stairs` 也对)。

### 自底向上写法(对比理解)

```python
def climb_stairs(n: int) -> int:
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]
```

进一步还能优化空间到 O(1):只留两个变量滚动(`a, b = b, a + b`),但 DP 表更直观,面试先讲表。

> 🟢 **Java 秒懂**:`dp` 数组那版几乎是 1:1 翻译(Java `int[] dp = new int[n+1];`)。
> 🟡 **差异**:`@lru_cache` 是 Python 独有的优雅;Java 记忆化要手写 memo。
> ⚠️ **坑**:`n<=2` 直接返回 `n`(即 `f(1)=1, f(2)=2`),别写成 `f(0)=0, f(1)=1` 再算——能对,但多绕一步容易写错边界。

### 复杂度

- 时间 O(n):每个子问题 `f(k)` 只算一次。
- 空间 O(n):递归栈深度 + lru_cache 缓存 n 项;自底向上空间 O(n),滚动优化 O(1)。

## §39.3 零钱兑换:coin_change(LC322)🟡

**题面**:给定硬币面额 `coins` 和金额 `amount`,凑成该金额的**最少硬币数**;凑不出返回 `-1`。每种硬币**无限个**(完全背包)。

### 为什么这么做 —— 为什么不能贪心

直觉是"每次挑最大面额尽量多拿"(贪心)。但贪心**会出错**:

```
coins=[1,3,4], amount=6
贪心: 4 + 1 + 1 = 3 枚   ← 错!
最优: 3 + 3     = 2 枚   ✓
```

贪心只顾眼前,会错过"两个 3 比 4+1+1 更优"的组合。**必须穷举所有子问题**——这就是 DP。

### 状态定义 + 转移

```
dp[i] = 凑成金额 i 所需的最少硬币数
转移: dp[i] = min( dp[i - coin] + 1 )   for coin in coins, if coin <= i
        ↑ 用一枚面额 coin 后,剩下的 i-coin 已经是最优,再 +1(这枚)
边界: dp[0] = 0     (金额 0 不需要硬币)
```

**哨兵技巧**:无法凑出的金额怎么表示?把 `dp` 初始化成 `amount + 1`(一个"不可能的大值")——因为最优答案最多用 `amount` 个 1 元硬币,真实答案**绝不可能超过 `amount`**。所以 `amount+1` 就是"无穷大"的替身。最后看 `dp[amount]`,若仍 `> amount` 说明不可达,返回 `-1`。

> 这是 DP 题里**最常见的哨兵模式**:用"理论上界 +1"代替 `float('inf')`,避免类型混乱,也方便 `min` 运算。

### 实现

```python
def coin_change(coins: list[int], amount: int) -> int:
    MAX = amount + 1                      # 哨兵 = 不可能的大值
    dp = [MAX] * (amount + 1)
    dp[0] = 0                             # 边界
    for i in range(1, amount + 1):
        for c in coins:
            if c <= i and dp[i - c] + 1 < dp[i]:
                dp[i] = dp[i - c] + 1
    return dp[amount] if dp[amount] != MAX else -1
```

**走一遍 `[1,2,5], amount=11`**:`dp[0]=0, dp[1]=1, dp[2]=1, dp[5]=1, dp[6]=2(5+1), ... dp[11]=3(10+1 / 6+5 / 9+2 的最优是 5+5+1)`。

### Java 对比

> 🟢 **Java 秒懂**:`int[] dp = new int[amount+1]; Arrays.fill(dp, amount+1); dp[0]=0;` 双层 for 一模一样。
> ⚠️ **坑**:
> 1. 忘了 `amount=0` 返回 0(题目明确 0 元要 0 枚)。
> 2. 哨兵写成 `float('inf')` 再 `+1` 会得到 `inf`,逻辑没错但最后比较 `> amount` 才是对的判据;新手容易直接 `return dp[amount]` 漏掉 `-1` 转换。
> 3. 内层循环 `if c <= i` 必须判,否则 `dp[i-c]` 越界。

### 复杂度

- 时间 O(amount × len(coins)):两层循环。
- 空间 O(amount):一维 dp 表。

## §39.4 最长递增子序列:length_of_lis(LC300)🟡

**题面**:给定整数数组,返回**严格递增子序列**的最大长度(子序列**不要求连续**,但要保序)。

### 为什么这么做

注意两个限定:**严格递增**(`nums[j] < nums[i]`,不能等于)+ **不连续**(可跳着选,区别于"子串/子数组"必须连续)。

经典 **一维 DP** 定义——以"位置 i 结尾"作状态:

```
dp[i] = 以 nums[i] 结尾的 LIS 长度
转移: dp[i] = max( dp[j] + 1 )   for all j < i 且 nums[j] < nums[i]
边界: dp[i] = 1   (至少包含 nums[i] 自己)
答案: max(dp)   (LIS 可能以任意位置结尾,取全局最大)
```

**走一遍** `[10,9,2,5,3,7,101,18]`:

| i | nums[i] | 能接在谁后面 (j) | dp[i] |
|---|---------|------------------|-------|
| 0 | 10 | (无) | 1 |
| 1 | 9 | (无,9<前面的10不行) | 1 |
| 2 | 2 | (无) | 1 |
| 3 | 5 | 2(2<5) | dp[2]+1=2 |
| 4 | 3 | 2(2<3) | dp[2]+1=2 |
| 5 | 7 | 2,5,3 | max(1,2,2)+1=3 |
| 6 | 101 | 2,5,3,7,9,10 | 3+1=4 |
| 7 | 18 | 2,5,3,7,9,10 | 3+1=4 |

`max(dp)=4`,答案 4(LIS 如 `[2,3,7,101]` 或 `[2,5,7,101]`)。

### 实现

```python
def length_of_lis(nums: list[int]) -> int:
    if not nums:
        return 0
    n = len(nums)
    dp = [1] * n              # 边界:每个元素自身是长度 1 的 LIS
    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i] and dp[j] + 1 > dp[i]:
                dp[i] = dp[j] + 1
    return max(dp)
```

### 进阶:O(n log n) 的 patience sorting(bisect)

面试官常追问"能不能更快"。**贪心 + 二分**思路:维护一个数组 `tails`,`tails[k]` = 长度为 k+1 的所有递增子序列的**最小末尾**。每来一个新数,用 `bisect_left` 找它该替换/追加的位置:

```python
import bisect
def length_of_lis_fast(nums):
    tails = []
    for x in nums:
        i = bisect.bisect_left(tails, x)   # 第一个 >= x 的位置
        if i == len(tails):
            tails.append(x)                 # x 比所有都大 -> 接长
        else:
            tails[i] = x                    # 否则替换,让末尾更小
    return len(tails)
```

注意:这个 `tails` **不是真实的 LIS**(只是长度对),但能求出**长度**且 O(n log n)。本章作业用 O(n²) 版本即可,进阶版面试加分。

### Java 对比

> 🟢 **Java 秒懂**:双层 for + `dp` 数组,完全 1:1。
> 🟡 **进阶差异**:Java 的二分要自己写或用 `Arrays.binarySearch`(返回负数表示插入点,要 `-i-1` 转换);Python 直接 `bisect.bisect_left`,语义清晰。
> ⚠️ **坑**:
> 1. 答案是 `max(dp)` 不是 `dp[-1]`——LIS 不一定以最后一个元素结尾。
> 2. 空数组返回 0(题面隐含),忘了判 `if not nums` 会 `max([])` 报错。
> 3. **严格递增**用 `<` 不是 `<=`;若题改成"非递减"才用 `<=`,别混。

### 复杂度

- DP 版:时间 O(n²),空间 O(n)。
- 进阶版:时间 O(n log n),空间 O(n)。

## §39.5 最长公共子序列:longest_common_subsequence(LC1143)🟡

**题面**:两个字符串 `text1`、`text2` 的**最长公共子序列**长度(可不连续,但保序)。

### 为什么这么做

两个串互相比——升到**二维状态**。经典定义:

```
dp[i][j] = text1 的前 i 个字符 与 text2 的前 j 个字符 的 LCS 长度
```

转移看最后那对字符 `text1[i-1]` 和 `text2[j-1]`(用 i-1 是因为字符串下标从 0,而 dp 从 1 开始留出"空前缀"边界):

```
若 text1[i-1] == text2[j-1]:   # 这对字符相等,可以配对收尾
    dp[i][j] = dp[i-1][j-1] + 1
否则:                          # 不等,各退一格取较大
    dp[i][j] = max(dp[i-1][j], dp[i][j-1])
边界: dp[0][*] = dp[*][0] = 0   # 空串和任何串的 LCS = 0
答案: dp[len1][len2]
```

**直观理解转移**:两字符相等,这俩就是 LCS 的一部分,前面的 LCS 长度 +1;不等,那这俩至少有一个**不进** LCS,分别尝试扔掉一个取较大。

**走一遍** `"abcde"` vs `"ace"`(dp 表 4×6,行是 abcde、列是 ace):

```
      ""  a   c   e
  ""   0  0   0   0
  a    0  1   1   1     # a==a -> dp[0][0]+1=1
  b    0  1   1   1     # b不配 -> max(上,左)
  c    0  1   2   2     # c==c -> dp[1][1]+1=2
  d    0  1   2   2     # 不配
  e    0  1   2   3     # e==e -> dp[4][2]+1=3
```

`dp[5][3]=3`,答案 3(即 `"ace"`)。

### 实现

```python
def longest_common_subsequence(text1: str, text2: str) -> int:
    len1, len2 = len(text1), len(text2)
    # dp 表开 (len1+1) x (len2+1),第 0 行/列全 0(空前缀边界)
    dp = [[0] * (len2 + 1) for _ in range(len1 + 1)]
    for i in range(1, len1 + 1):
        for j in range(1, len2 + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[len1][len2]
```

### Java 对比 + 二维表的常见写法

> 🟢 **Java 秒懂**:`int[][] dp = new int[len1+1][len2+1];` 几乎逐字翻译。
> 🔴 **Python 特有**:**二维 list 的初始化**是个经典坑——
> ```python
> dp = [[0] * (len2 + 1)] * (len1 + 1)   # ❌ 错!所有行是同一个对象
> dp = [[0] * (len2 + 1) for _ in range(len1 + 1)]   # ✓ 每行独立
> ```
> `[x]*n` 对**不可变**元素(0)是安全的,但 `[[..]]*n` 会让 n 行指向**同一行**,改一个全变。**必须用列表推导式**。这是 Java 老手写 Python 二维表的第一大坑(Java 的 `new int[][]` 天然每行独立,没有这问题)。
> ⚠️ **其他坑**:`i-1`/`j-1` 别越界(所以从 1 开始循环);别把 `dp[i-1][j-1]+1` 写成 `dp[i][j]+1`(自引用)。

### 复杂度

- 时间 O(len1 × len2):填满整张表。
- 空间 O(len1 × len2);滚动数组可优化到 O(min(len1,len2))。

## §39.6 编辑距离:min_distance(LC72 Hard)🔴

**题面**:把 `word1` 变成 `word2`,最少需要几次**单字符操作**?操作有三种:**插入 / 删除 / 替换** 一个字符。

### 为什么这么做 —— LCS 的升级版

这是二维 DP 的天花板题之一。和 LCS 几乎同构,但相等时要看"不操作",不等时**多了替换**。状态:

```
dp[i][j] = word1 前 i 个字符 变成 word2 前 j 个字符 的最少操作数
```

转移:

```
若 word1[i-1] == word2[j-1]:   # 这对字符已相等,白嫖,不操作
    dp[i][j] = dp[i-1][j-1]
否则:                          # 不等,三选一取最小 +1
    dp[i][j] = 1 + min(
        dp[i-1][j],      # 删除 word1[i-1]    (word1 退一格)
        dp[i][j-1],      # 插入(=在 word1 加 word2[j-1],word2 退一格)
        dp[i-1][j-1],    # 替换 word1[i-1] 成 word2[j-1]
    )
边界:
    dp[i][0] = i   # 把 word1 前 i 个全删了变空串
    dp[0][j] = j   # 从空串插入 j 个字符变 word2 前 j 个
```

**三种操作怎么对应三个邻居**(画表秒懂):
- `dp[i-1][j]` 是**上方** → word1 多消耗一个字符(删掉它)。
- `dp[i][j-1] 是**左方** → word2 多匹配一个(在 word1 插入它)。
- `dp[i-1][j-1]` 是**左上** → 两个指针都前进(替换,或相等时白嫖)。

**走一遍** `"horse"` → `"ros"`(简略):最终 `dp[5][3]=3`(horse→rorse→rose→ros)。

### 实现

```python
def min_distance(word1: str, word2: str) -> int:
    len1, len2 = len(word1), len(word2)
    dp = [[0] * (len2 + 1) for _ in range(len1 + 1)]
    # 边界:空串
    for i in range(len1 + 1):
        dp[i][0] = i
    for j in range(len2 + 1):
        dp[0][j] = j
    for i in range(1, len1 + 1):
        for j in range(1, len2 + 1):
            if word1[i - 1] == word2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]   # 白嫖
            else:
                dp[i][j] = 1 + min(
                    dp[i - 1][j],      # 删
                    dp[i][j - 1],      # 插
                    dp[i - 1][j - 1],  # 替
                )
    return dp[len1][len2]
```

### Java 对比

> 🟢 **Java 秒懂**:二维 `int[][]`,三层填表逻辑完全一致。Hard 的"难"在**想到状态定义**,不在语言。
> 🟡 **差异**:同样是 `[[0]*w]*h` 的初始化坑(见 §39.5),用列表推导式。
> ⚠️ **坑**:
> 1. **边界别漏**:空串情况 `dp[i][0]=i`、`dp[0][j]=j` 必须显式填,否则默认 0 会把"全删/全插"算成 0 次。
> 2. 字符相等时是 `dp[i-1][j-1]`(**不加 1**,白嫖),不等时才 `+1`——两者别混。
> 3. 别忘了 `min` 里**三个**分支,漏掉"替换"会退化成只能增删(那是另一道题:只有增删的编辑距离 = `len1+len2-2*LCS`)。

### 复杂度

- 时间 O(len1 × len2):填满整张表。
- 空间 O(len1 × len2);滚动数组优化到 O(min(len1,len2))。

## §39.7 DP 通用方法论 + 原型速查(讲透不出题)

### 解 DP 题的四步套路(背下来)

1. **定义状态**:`dp[i]` / `dp[i][j]` 代表什么?(一句话,要"无后效")
2. **写转移方程**:`dp[i]` 从哪些状态来?取 `max`/`min`/`+`?
3. **定边界 + 初始值**:最小子问题直接给答案(如 `dp[0]=0`),不可达用哨兵。
4. **确定计算顺序 + 答案位置**:自底向上从小填大;答案在 `dp[n]` 还是 `max(dp)`?

### 五大原型速查表

| 原型 | 代表题 | 状态 | 转移核心 |
|------|--------|------|----------|
| 一维递推(斐波那契型) | 爬楼梯 §39.2 | `dp[i]`=到 i 的方案数 | `dp[i]=dp[i-1]+dp[i-2]` |
| 背包(完全/0-1) | 零钱兑换 §39.3 | `dp[i]`=凑 i 的最少/方案 | `dp[i]=min(dp[i-c]+1)` |
| 一维区间(LIS 类) | LIS §39.4 | `dp[i]`=以 i 结尾 | `dp[i]=max(dp[j]+1)` |
| 双串公共(LCS 类) | LCS §39.5 | `dp[i][j]`=前 i × 前 j | 相等 +1,否则 max(上,左) |
| 双串变换(编辑距离类) | Edit §39.6 | `dp[i][j]`=i→j 的代价 | 相等不变,否则 min(增删改)+1 |

## §39.8 Java 老手常踩的坑 ⚠️

1. **裸递归不记忆化**:斐波那契、爬楼梯写裸递归 → O(2ⁿ) 超时。要么 `@lru_cache`,要么填表。
2. **二维表用 `[[0]*w]*h`**:`*` 复制是浅拷贝,所有行指向同一对象,改一个全变。**必须列表推导式** `[[0]*w for _ in range(h)]`(§39.5/§39.6 大坑)。
3. **答案取错位置**:LIS 答案是 `max(dp)` 不是 `dp[-1]`(LIS 不一定以末尾结束);爬楼梯答案在 `dp[n]`。
4. **哨兵漏判**:`coin_change` 不可达要返回 `-1`,别直接 `return dp[amount]`(可能是哨兵)。
5. **边界不填**:编辑距离的 `dp[i][0]=i`、`dp[0][j]=j` 必须显式填,否则全算成 0。
6. **严格 vs 非严格搞混**:LIS 用 `<`(严格),题改"非递减"才用 `<=`。
7. **三操作漏分支**:编辑距离 `min(删,插,替)` 三个都要,漏"替换"答案错。
8. **`@lru_cache` 加在错的函数上**:可变参数(list)不能 hash → 不能缓存;要缓存就把 list 转 tuple,或缓存下标版。

## 🔖 闪卡

| # | 正面(问题) | 背面(答案) | 掌握 |
|---|---|---|---|
| 1 | 把函数当参数传,为什么写 `fn` 不能写 `fn()`? | `fn` 是函数【对象本身】;`fn()` 是【调用】它拿返回值。传参/返回时不带括号,否则传进去的是调用结果 | ⬜ |
| 2 | 闭包是什么?为什么外层函数返回后,被捕获的变量还活着? | 内层函数 + 它记住的外层变量。内层函数持有外层变量的引用,只要内层函数还在,那些变量就不被回收。≈ Java lambda 捕获 effectively final | ⬜ |
| 3 | 循环里造闭包有什么坑?怎么破? | 闭包对循环变量是**晚点绑定**:循环结束后共享同一个终值。用默认参数 `t=t` 把当期值「拍下来」 | ⬜ |
| 4 | `*args` 和 `**kwargs` 在函数内分别是什么类型? | `*args` → **元组** tuple;`**kwargs` → **字典** dict | ⬜ |
| 5 | 手上有列表 `prices`,怎么传给 `cart_total(*prices)` 这类变参函数?直接传会怎样? | 调用处用 `*` 打散:`cart_total(*prices)`。直接传会把整个 list 塞进元组的第一个位置(Java varargs 能直接传数组,Python 不行) | ⬜ |
| 6 | `@deco` 贴在 `def f` 上面,等价于哪一句?装饰在何时执行? | `f = deco(f)`——装饰器在【定义时】执行一次,把 f 替换成包装版 | ⬜ |
| 7 | 装饰器的 wrapper 为什么必须用 `*args, **kwargs`? | 为了接住【原函数任意签名】的调用,再原样 `func(*args, **kwargs)` 转发。写死参数就限制了原函数 | ⬜ |
| 8 | `@functools.wraps(func)` 干嘛的?不加会怎样? | 把原函数的 `__name__`/`__doc__` 等拷贝给 wrapper。不加的话装饰后 `f.__name__` 变成 `"wrapper"`,调试/反射/FastAPI 全乱 | ⬜ |
| 9 | 装饰器的标准骨架(计数/计时通用)长什么样? | 「前:做点事(记起点/加计数)→ `result = func(*args, **kwargs)` → 后:做点事 → 原样 return」;状态挂函数属性(`wrapper.xxx`),初值在 return 前设置 | ⬜ |
| 10 | 带参数的装饰器(如 `@retry(times=3)`)要写几层?每层 return 什么? | **三层**:`factory(args)` return decorator;`decorator(func)` return wrapper;`wrapper` 实际替换原函数。等价 `f = retry(times=3)(f)` | ⬜ |
| 11 | `retry` 的 `raise last_exc` 为什么放循环外? | 放循环内第一次失败就抛,失去重试意义;循环走完才抛 = 「times 次机会都用完」,且抛的是【最后一次】异常 | ⬜ |
| 12 | `memoize` 的 cache 为什么要放闭包位?放 wrapper 内/模块全局各有什么后果? | 闭包变量「每次装饰」新建一份 → 每个被装饰函数独立缓存。放 wrapper 内 → 每次调用新建,永远 miss;放全局 → 各函数共用一本账,键互相串 | ⬜ |
| 13 | lambda 的限制是什么?什么时候该用 def? | lambda **只能写一个表达式**,不能写语句(赋值/for 都不行)。复杂逻辑用 def,别堆 lambda | ⬜ |
